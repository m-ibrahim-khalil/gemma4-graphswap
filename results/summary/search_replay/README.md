Search-path files for `search_similar_code` in Phases A and B. No query strings, node text or task text.

- `summ_<run>.csv`: the per-task run CSV (same as `results/runs/<run>.csv`) with the `search_*` columns. Regenerated by `graphswap summarize --graphs DIR`.
  - Columns: `search_calls` = `search_similar_code` calls in the task's trace; `search_resolved` = calls whose query resolved to a graph node (embedding path; includes the substring tier); `search_lexical` = calls that fell back to lexical matching; `search_substring` = resolved calls matched only by the substring tier (arbitrary anchor).
  - A_C0_1234, A_C0_4321: C0 has no graph tools, so all search columns are zero. Classified against the released graphs.
  - A_C1_1234, A_C1_4321, A_C2_1234, A_C2_4321: classified against the released graphs.
  - A_C3_1234, A_C3_4321: classified against the rebuilt graphs (`bundles/graphs_rebuilt`).
  - B_C1_1234, B_C1_4321 (Phase B, 60 tasks): classified against the released graphs. Their run CSVs under `results/runs/` carry the same columns.
  - B_C3_1234, B_C3_4321 (Phase B): classified against the rebuilt graphs (`bundles/graphs_rebuilt`); classification only, no replay.
  - B_C0_1234, B_C0_4321 (Phase B): C0 has no graph tools, so all search columns are zero, as for A_C0.
- `replay.summary.csv`: offline replay of every search call under released embeddings (set A) vs released-node Qwen3 embeddings (set B), per call. Runs: A_C1_1234, A_C1_4321, A_C2_1234, A_C2_4321, B_C1_1234, B_C1_4321 (released graphs); the run name carries the phase. The Phase B rows (B_C1_1234, B_C1_4321) are present for completeness; the writeup quotes only the four Phase A rows and does not cite the Phase B ones at all (their set-level reproduction counts are in the note at the end of this file).
- `replay_dedupe.summary.csv`: the same, plus a `unit=query` row per run counting each (task, query, k) once. Regenerated with the dedupe key that includes `k`; the unit=call rows are identical to `replay.summary.csv`. Against the earlier file (which keyed on (task, query) only) the `unit=query` rows of A_C1_1234, A_C1_4321 and A_C2_4321 gained 1, 3 and 1 queries; A_C2_1234 is unchanged.

Both summaries come from one run each of `graphswap replay-search` over all six runs (`--dedupe` for the second); the per-call rows (`--out`) hold query strings and are not committed. Set A = released embeddings, set B = `bundles/emb_released_nodes_raw`.

Both `.summary.csv` files begin with a `#` comment line; read them with `pd.read_csv(path, comment='#')`.

Note on `observed_a_embed` / `observed_b_embed` (Task 15p review, 2026-11-02): these count exact, ordered matches between the replayed and the recorded result list. Every B_C1 mismatch (8 at seed 1234, 11 at seed 4321) has the same node set as the recorded list and differs only in order, between nodes whose float32 cosines differ by at most ~1.2e-7 (ties inside float rounding noise between the recording and the replaying machine; only 1 and 2 of those calls swap bit-identical duplicate vectors). As sets, set A reproduces 134/134 and 157/157 recorded B_C1 lists. The denominators (`n_observed_embed`) exclude 18 and 19 resolved calls whose trace records no embedding-path result list. Phase A shows the same order-only pattern apart from one call with a genuinely different set.
